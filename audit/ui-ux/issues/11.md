## Problem

Every settings section keeps edits in client state until Save. Navigating to another section, using the mobile section switcher, or following a link away from Settings loses the edit with no warning, dirty indicator, or draft restoration. The public intake form does warn ("Discard this draft?"); settings does not.

## Affected routes

- All `/settings/*` sections, especially long forms: `/settings/session`, `/settings/planning`, `/settings/availability`, `/settings/repositories`.

## Steps to reproduce

1. Open `/settings/session`.
2. Change Idle lifetime from 30 to 45 (do not save).
3. Click `Features` in the settings sidebar, then return to `Session`.
4. Repeat using the mobile section switcher.

## Actual behavior

Navigation happens immediately; the field returns to 30. No confirmation, toast, unsaved marker, or draft is shown.

## Expected behavior

Leaving a dirty settings form warns before discarding, or preserves the draft until Save/Discard. A visible dirty state makes the pending change obvious.

## Impact

A user who fills a multi-field page and then checks another section can lose the entire edit without noticing. It is a data-loss trap in the main configuration workflow.

## Suggested direction

Track a dirty flag in `SettingsForm`, expose it to the settings layout, and guard `beforeNavigate`/section switching with a Bootstrap modal or `window.confirm`, consistent with `/intake`. Alternatively preserve per-section drafts.

## Acceptance criteria

- [ ] Editing any settings field marks the section dirty.
- [ ] Leaving a dirty section prompts before discarding, including the mobile switcher.
- [ ] Saving or explicitly discarding clears the dirty state.

**Priority:** P2 — silent loss of configuration edits.
