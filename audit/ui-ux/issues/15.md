## Problem

`StatusText` replaces the issue's status with other vocabulary in common states:

- When `blocked` is true, it renders "Blocked" instead of the status. On `/issues`, FUN-6 appears as "Blocked" inside the "In Progress" group, and FUN-8/FUN-7 appear as "Blocked" under Backlog/Todo. Filtering `?status=in-progress` returns a row labelled "Blocked".
- When no status is passed, it falls back to "Unconfirmed". The epic detail passes only `state`, so an open Backlog/Todo epic is labelled "Unconfirmed" on its detail page while `/epics` says "Open" and the issue Properties say "Backlog".
- An untriaged issue detail shows "Unconfirmed" in the header but "No status" in the Properties select.

Status, blocked and missing status are three separate dimensions. The current component conflates them and uses triage vocabulary as a generic fallback.

## Affected routes

- `/issues`, `/epics/[owner]/[repo]/[number]`, issue detail headers, and any surface using `StatusText`.

## Steps to reproduce

1. Open `/issues?status=in-progress` and compare the group header with FUN-6's Status cell.
2. Open `/epics/demo/funnel/10`; the meta line says "Unconfirmed".
3. Open `/epics` and the same epic's issue detail; they say "Open" and "Backlog".
4. Open an untriaged issue detail and compare header and Properties.

## Actual behavior

Status cells contradict their group and filter; epic detail contradicts the list and issue; "Unconfirmed" appears for ordinary Backlog/Todo work.

## Expected behavior

Always show the real status. Render blocked as a separate visible and accessible indicator (for example "In progress · Blocked"). Use "No status" only when a status is genuinely absent; never use "Unconfirmed" as a fallback.

## Impact

Users cannot trust the status column for filtering or grouping, and a normal Backlog epic looks like an unresolved exception.

## Suggested direction

Keep `StatusText` status-only and render blocked separately. Pass the epic's real status on its detail page. Replace the `Unconfirmed` default with a neutral "No status" and align the untriaged header with the Properties label.
