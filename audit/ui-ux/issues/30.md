## Problem

Clicking an issue title swaps the `h1` for a borderless input with no Save/Cancel buttons, no visible editing affordance and no hint. Pressing Escape cancels (undiscoverable), but blurring or pressing Tab commits the change silently with no success message or undo. The description editor 40px below has explicit Cancel/Save buttons, so two adjacent editors use different conventions.

## Affected routes

- `/issues/[owner]/[repo]/[number]`.

## Steps to reproduce

1. Open an issue and click the title.
2. Change the text, then click elsewhere or press Tab.
3. Reopen the issue; the change is saved without confirmation.

## Actual behavior

The input is indistinguishable from static text except for a caret. Blur commits silently; Escape cancels invisibly.

## Expected behavior

Editing mode is obvious and Save/Cancel are discoverable, or a visible hint states "Enter to save · Esc to cancel" and a success state confirms the commit. Behavior matches the description editor.

## Impact

Accidental edits persist without the user knowing, while intended edits may be abandoned because there is no obvious way to save.

## Suggested direction

Use a small inline form with Save/Cancel beside the input, or commit on Enter and revert on blur unless explicitly saved. At minimum add a visible hint and saved feedback.

- [ ] Entering title edit mode is visually obvious.
- [ ] Save and cancel are discoverable.
- [ ] A committed title shows feedback consistent with other writes.
- [ ] Escape and blur behavior are documented in the UI.
