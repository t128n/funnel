## Problem

In the Epics table the title cell is a plain `<span>`; only the small `demo/funnel#10` reference is a link. Clicking the title — the largest and most conventional target — does nothing. On `/milestones`, the milestone title is a link, so two visually identical list pages behave differently. Composition A §7.4 makes the title the primary link and requires keyboard and middle-click access.

## Affected routes

- `/epics` at 1440×900, 768×1024 and 390×844.

## Steps to reproduce

1. Open `/epics`.
2. Click the text of an epic title.
3. Observe the URL remains `/epics`.
4. Click the small reference; the detail opens.

## Actual behavior

The title is not interactive. On mobile the only target is a 12px reference, and the title itself is clipped at the table edge.

## Expected behavior

The epic title is a blue link to the epic detail (or the row is a real link), focusable and middle-clickable, matching the Milestones list and the Issues table.

## Impact

Users follow the standard "click the title" habit and get no response. Keyboard and middle-click navigation are unavailable through the natural target.

## Suggested direction

Wrap the title in an anchor and keep the reference as secondary text or a second link. Optionally make the row clickable following the shared issue-row pattern.

## Acceptance criteria

- [ ] Clicking an epic title opens its detail page.
- [ ] The title link has a visible focus state and supports middle-click.
- [ ] The Epics and Milestones lists use the same title-link convention.

**Priority:** P2 — standard list navigation does not work.
