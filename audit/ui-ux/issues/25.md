## Problem

When the Inbox has items but the search matches none, the page renders the same green success alert used for a genuinely empty queue: "Inbox is clear. Nothing is waiting for triage." The navbar badge still says "Inbox 6", while the summary reads "0 submissions · 0 untriaged issues". There is no "no results" explanation or clear-search action in the empty region.

## Affected routes

- `/inbox?q=<no match>` at all widths.

## Steps to reproduce

1. Open `/inbox` with pending items.
2. Type `zzzz` in Search inbox.
3. Compare the alert, summary and navbar badge.

## Actual behavior

A success state claims the queue is clear while six items are waiting. Counts contradict the badge.

## Expected behavior

Distinguish an empty queue from an empty result set. The no-match state says no items match the search, keeps totals or labels them as filtered, and offers "Clear search". The success alert appears only when the underlying queue is empty.

## Impact

A user can conclude the queue is empty while items are waiting, especially when the navbar count is out of sight on mobile. The summary becomes untrustworthy.

## Suggested direction

Branch on the unfiltered total (or active filters) before rendering the success alert. Reuse the issue index's "No items match this view" pattern with a Clear search button.

## Acceptance criteria

- [ ] A no-match search shows a neutral empty-results message, not the success alert.
- [ ] The success alert appears only when the queue is genuinely empty.
- [ ] A clear-search action is available in the no-match state.
- [ ] Counts are labelled consistently with the active filter.

**Priority:** P2 — a filtered view falsely reports that work is finished.
