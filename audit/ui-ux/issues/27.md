## Problem

Navbar dropdowns do not implement the standard Bootstrap keyboard/ARIA contract:

- Opening **More**, repository scope, theme or account with the keyboard leaves focus on the toggle. ArrowDown/ArrowUp do not move into the menu.
- Escape does not close an open menu, even when focus is on a menu item; the menu only closes when Tab leaves it.
- Repository and theme selections communicate state visually only. The active item has `.active` or an `aria-hidden` check icon, with no `aria-current`, `aria-checked` or `role="menuitemradio"`.

## Affected routes

- Every app route via the navbar menus.

## Steps to reproduce

1. Focus **More** and press Enter; press ArrowDown.
2. Tab into an item and press Escape.
3. Open Theme or Repository scope and inspect the selected item's ARIA state.

## Actual behavior

Arrows do nothing, Escape leaves the menu open, and screen readers cannot tell which theme or repository is selected.

## Expected behavior

Arrow keys move through menu items; Escape closes and returns focus to the toggle; the current repository/theme is announced as selected/current. This matches Bootstrap's dropdown behavior.

## Impact

Keyboard users must tab through every item and cannot dismiss menus conventionally. Non-visual users cannot confirm the current scope or theme before choosing.

## Suggested direction

Add keydown handling to a shared dropdown wrapper (Escape, ArrowDown, ArrowUp, Home/End) or configure Sveltestrap accordingly. Use `role="menuitemradio"` + `aria-checked` for single-choice menus while keeping the visual check.
