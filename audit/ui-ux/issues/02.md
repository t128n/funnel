## Problem

After a card is moved to another lane, the source lane keeps rendering the moved card. The lane header count updates, but the virtualized card list does not, so the same issue appears in two lanes and the header count contradicts the visible cards. Reproduced with pointer drag-and-drop and with the Space/arrow keyboard move; reloading removes the stale copy.

## Affected routes

- `/board` at 1440×900, light and dark.

## Steps to reproduce

1. Open `/board`.
2. Drag FUN-7 from Todo to In Review.
3. Wait for the optimistic update and SSE refresh.
4. Compare the Todo header count with the rendered cards.

## Actual behavior

Todo header reads `2` but three cards render (PLT-6, FUN-14, FUN-7), and FUN-7 also appears in In Review. The keyboard move of FUN-3 from Todo to In Progress produces the same duplicate until a page reload.

## Expected behavior

After any move, the card appears only in its destination lane and every lane header count equals the number of rendered cards. No reload is required.

## Impact

The board shows contradictory state after every move. The stale duplicate remains interactive, so a user can open or move the wrong copy and issue a second unintended state change. Users who trust the lane count cannot tell whether the move succeeded.

## Suggested direction

Reseed/invalidate the virtualized source lane when the local lane arrays change, rather than only updating the count. Keep stable keys (`repo#number`) and replace Virtua's data list rather than mutating it in place. Cover both pointer and keyboard remove paths in a component test.
