## Problem

An issue can carry `Planned: This week · 2 Nov` while having no size. That is the seeded state of FUN-4: its Properties show "This week · 2 Nov", the board card shows "2 Nov 2026", but `/plan` for that week says "Nothing is planned for this week", shows 0m in every lane, and lists FUN-4 only under "Unestimated" with no indication that it is committed. Clearing an issue's size after scheduling (allowed from Properties) creates the same state.

## Affected routes

- `/plan?week=2026-11-02`, `/issues/demo/funnel/4`, `/board`.

## Steps to reproduce

1. Open `/issues/demo/funnel/4` and confirm Planned = "This week · 2 Nov", Size = "Not estimated".
2. Find FUN-4 on `/board` with its planned marker.
3. Open `/plan` for the week of 2 Nov 2026.

## Actual behavior

The plan claims nothing is planned and counts no committed minutes; the issue appears only in the unestimated list. Board and plan disagree about the same issue.

## Expected behavior

Either prevent clearing size while an issue is planned, or show the committed-but-unestimated issue in its maintainer lane with an "estimate to count" warning. The page must never say "Nothing is planned" when any issue is committed for the week.

## Impact

Capacity is wrong, the same issue can be double-booked, and trust in the planning model erodes.

## Suggested direction

Include planned issues with a null size in `plannedCount` and in a lane-level "needs estimate" row. Distinguish counted minutes from unsized commitments in the capacity text. Alternatively reject size removal for planned issues at the write path.

## Acceptance criteria

- [ ] A planned issue with no size is visible as planned in its lane, or blocked from reaching that state.
- [ ] The empty-week state is not shown when any issue is committed.
- [ ] Capacity text distinguishes counted minutes from unsized commitments.
- [ ] Board and plan agree on whether the issue is planned.

**Priority:** P2 — capacity is wrong and the two views contradict each other.
