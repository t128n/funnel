## Problem

Below `lg`, the navbar is a collapsible menu. Primary links close it, but choosing a repository, choosing Account/Settings from the account menu, or tapping the `funnel` brand navigates without closing it. The expanded menu remains on top of the destination page and hides its title and content.

## Affected routes

- All app routes at 390×844; reproduced `/inbox` → `/settings`, `/board` → repository scope, `/board` → `/issues` via brand.

## Steps to reproduce

1. At 390×844 open `/inbox` and tap the hamburger.
2. Tap **Account menu → Account**.
3. Observe the menu state and the Settings page underneath.
4. Repeat with **Repository scope → demo/platform** and with the `funnel` brand.

## Actual behavior

The app navigates, but `aria-expanded` stays `true` and the 386px menu remains expanded over the new page. On `/settings` it hides the page title and section navigation. The user must find the hamburger and tap it again.

## Expected behavior

Every navigation initiated from the collapsed menu closes it. `aria-expanded` matches the visual state, and focus is not left on a hidden menu item.

## Impact

On the required mobile viewport, part of every affected navigation appears to fail. Users can believe the destination did not open.

## Suggested direction

Close the menu in `setRepo`, `openSettings`, the brand click handler, and any other handler that navigates. Prefer a single navigation wrapper so future items cannot forget it. Add a regression test at 390px.
