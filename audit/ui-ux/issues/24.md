## Problem

Filtering is split across two unrelated surfaces with no cue about which dimension lives where. On `/issues`, the toolbar holds Search, Status, Priority, Assignee and Group, while a separate **Filters** link opens a 400px right offcanvas holding State, Repo, Size, Labels, Planned and Milestone. State (Open/Closed/All) — the most consequential scope switch — exists only in the drawer. The drawer repeats the word "Filters" as heading and first body line, and its badge counts the search term even though its Clear does not clear search.

On `/board` and `/matrix`, the same offcanvas is a 400px mostly empty drawer with eight unlabeled dropdown buttons and roughly 700px of blank space. No filter labels, active-filter summary, Apply or Clear are visible. The drawer covers the view it filters.

## Affected routes

- `/issues`, `/board`, `/matrix` at desktop and narrow widths.

## Steps to reproduce

1. Open `/issues`, note the toolbar, then click Filters and compare the two sets of controls.
2. With only `?q=cockpit` active, open Filters and press Clear; the query remains.
3. Open `/board` and click Filters; observe the empty drawer and hidden active state.

## Actual behavior

Users must hunt in two places; the count and Clear actions disagree; the drawer hides state and covers the canvas. It is a slide-over pattern in an otherwise conventional Bootstrap page.

## Expected behavior

One predictable filtering surface. At `lg+`, the primary dimensions (including State) are visible in the single toolbar row; the offcanvas, if retained for long-tail filters, groups dimensions under headings, shows active filters, and provides a consistent Clear. The badge count equals what Clear removes.

## Impact

Filtering takes more clicks and hides active state on the three main list surfaces. Users can miss that closed issues or other dimensions are scoped.

## Suggested direction

Promote State/Status/Priority/Assignee into the existing toolbar row as `form-select-sm` controls. Keep only long-tail dimensions in the drawer, label it "More filters", show active filters as removable chips, and make Clear/badge semantics consistent.

## Acceptance criteria

- [ ] Every primary filter dimension is reachable from one clearly labelled surface.
- [ ] At 1440px, Status/Priority/Assignee/State are visible without opening a panel.
- [ ] The active-filter badge and Clear action cover exactly the same set.
- [ ] The offcanvas, if kept, has grouped headings and does not look empty.
- [ ] No second toolbar row is added.

**Priority:** P2 — filtering is harder to discover and its state is unreliable.
