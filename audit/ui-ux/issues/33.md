## Problem

On a phone the issue detail DOM order is document → Activity → Work notes → Attachments → Properties → Details. On `/issues/demo/funnel/1` at 390×844 the Properties card begins about 1660px down a 3061px page, after the full description, three comments, the composer, work notes and attachments. Changing status, assignee or milestone requires a long scroll, and there is no jump control or sticky metadata summary near the header. The status shown in the header is not an affordance.

## Affected routes

- `/issues/[owner]/[repo]/[number]` below `lg`, measured at 390×844 and 768×1024.

## Steps to reproduce

1. Open `/issues/demo/funnel/1` at 390×844.
2. Try to change status or assignee without scrolling to the bottom.
3. Measure the Properties heading position.

## Actual behavior

Properties is roughly two viewports below the header, after the entire conversation. No shortcut or summary is available.

## Expected behavior

Metadata editing is reachable without traversing the conversation. Composition A leaves the exact mobile order open; either place Properties before Activity on narrow screens, or provide a compact metadata summary/jump action near the header.

## Impact

Mobile triage and status updates are slow and easy to abandon, and users may not discover that the fields are editable.

## Suggested direction

On `<lg`, place Properties (and Details) before Activity, or add a small Properties anchor/button next to the meta row that jumps to the card. Keep the desktop 8/4 document-first order unchanged.

**Priority:** P2 — the main metadata workflow is buried on mobile.
