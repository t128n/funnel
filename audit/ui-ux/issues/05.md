## Problem

The navbar advertises a global **Search** control with a `Ctrl K` hint, but it opens no search surface. It calls `focusSearch()`, which focuses whichever element has `id="issue-search"` on the current page, or redirects to `/issues` when none exists. Search scope therefore changes silently by route: it filters Inbox submissions on `/inbox`, board cards on `/board`, the issue index on `/issues`, and abandons Settings, Notifications or an issue document entirely.

The index search also promises "issue ID" support in its placeholder, but identifiers like `FUN-1` never match, while title words do.

## Affected routes

- Every app route through the navbar Search control and `Ctrl/Cmd+K`.
- `/issues`, `/inbox` and `/board` page-local search fields.

## Steps to reproduce

1. Open `/inbox`, click **Search**, and type `postgres`. Only the Inbox queue is filtered.
2. Open `/settings` and press `Ctrl K`. The browser navigates to `/issues` and focuses that page's filter.
3. On `/issues`, type `FUN-1`. The result is the empty state; type `flicker` and the issue is found by title.

## Actual behavior

No global result list, no cross-repository query, no Enter/Escape contract. On several routes the global shortcut performs an unexpected navigation. The placeholder claims identifier search that does not exist.

## Expected behavior

A single global search surface reachable from the navbar and `Ctrl/Cmd+K`, with results across repositories, Enter to open the first result, Escape to close, and focus returned to the trigger. Page-local filters stay independent. Placeholder text matches the fields actually searched; identifier search works or is no longer promised.

## Impact

The most prominent control in the shell behaves differently on every route and loses user context. The conventional issue-tracker lookup (`FUN-1`) silently fails and looks like the issue does not exist.

## Suggested direction

Implement the Composition A search panel (or reuse the product's existing index) behind the navbar button and `Mod+K`. Keep page-local filter fields separate. Either teach the query path `owner/name#number` identifiers or change the placeholder to the implemented fields until #21 lands.

## Acceptance criteria

- [ ] Navbar Search and `Mod+K` open the same global surface from every app route.
- [ ] Results include issues from all repositories regardless of the current page.
- [ ] Enter opens the first result; Escape closes and restores focus to the trigger.
- [ ] Page-local filters are not focused by the global shortcut.
- [ ] Identifier queries work, or the placeholder no longer promises them.

**Priority:** P2 — the advertised global discovery workflow is missing.
