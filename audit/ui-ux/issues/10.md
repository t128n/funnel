## Problem

Several dialogs open without moving focus into the dialog and without trapping it. With the board's Done dialog open, `document.activeElement` is `<body>` and Tab moves to the next board card behind the overlay. In Settings, destructive confirmations open with focus on `body`, Tab reaches page controls behind the modal first, and the dialog has `role="dialog"` but no `aria-modal` or accessible name. The Matrix assessment queue and Rating guide leave focus on their triggers. Closing does not restore focus to the invoking control.

## Affected routes

- `/board` (Close issue dialog), `/matrix` (Assessment queue, Rating guide), `/settings/repositories`, `/settings/projects`, `/settings/availability`, `/settings/github-app` (confirmation dialogs).

## Steps to reproduce

1. Open `/board`, drag a card into Done, and inspect `document.activeElement`; press Tab.
2. Open `/matrix` → Review queue; inspect focus and Tab order.
3. Open `/settings/repositories` → row Actions → Remove repository; inspect `aria-modal`/`aria-labelledby` and Tab order.

## Actual behavior

Focus stays on the trigger or `body`; background controls remain tabbable; dialogs lack `aria-modal` and accessible names; focus is not restored on close.

## Expected behavior

On open, focus moves to the dialog (first field or close button), Tab/Shift+Tab cycle only inside it, background content is inert, Escape closes, and focus returns to the trigger. Dialogs expose `aria-modal="true"` and an accessible name.

## Impact

Keyboard and screen-reader users must tab through all background content to reach a confirmation, and some will not discover the dialog is open. This affects every destructive confirmation and planning dialog.

## Suggested direction

Use the project's existing `focusTrap` helper (already used by `FilterPopover`) or native `<dialog>`/Bootstrap focus management. Set initial focus explicitly, mark `aria-modal`, and restore the previously focused element on close.

## Acceptance criteria

- [ ] Opening any dialog moves focus into it.
- [ ] Tab and Shift+Tab cycle only through dialog controls.
- [ ] Dialogs expose `aria-modal="true"` and an accessible name.
- [ ] Escape closes and returns focus to the invoking control.
- [ ] Background controls are not reachable while a dialog is open.

**Priority:** P2 — keyboard users cannot reliably complete destructive and planning flows.
