## Problem

With blocks on the day, `/day` overflows horizontally at 390px. `.day-layout` has a single implicit grid track that sizes to content (647.6px) inside a 358px content area, making the document 664px wide. The timeline is 647.6px and each block 573.6px; the block's right-side duration and Remove controls sit off-screen. The 09:00–13:00 block extends past the visible timeline.

## Affected routes

- `/day` at 390×844 (light and dark).

## Steps to reproduce

1. Open `/day` and click Auto-plan so at least one block exists.
2. Set the viewport to 390×844.
3. Check `document.documentElement.scrollWidth` and try to reach the block's Remove control.

## Actual behavior

`scrollWidth` is 664 > 390. The page scrolls horizontally; controls on the right of blocks are unreachable without sideways page scrolling.

## Expected behavior

No page-level horizontal scrolling at 390px. The timeline fits the column or scrolls inside its own bounded container; block controls remain reachable.

## Impact

The required mobile viewport is broken: content is wider than the screen and horizontal scrolling fights the vertical timeline. Composition A explicitly requires no horizontal page overflow at 390px.

## Suggested direction

Set `.day-layout { grid-template-columns: minmax(0, 1fr); }` at the base breakpoint and `min-width: 0` on grid children. If the hour row needs a minimum width, wrap `.day-timeline` in an overflow-x container so only the chart scrolls. Keep the candidate aside full width.
